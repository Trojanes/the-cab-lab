## A01 · Cab Agent 执行安全（P0）

**改动入口**：`renderer/commands.js`、`mcp.mjs`、`cli.mjs`、`scripts/agent-run.mjs`；测试就近新增。
**要求**：
1. `invoke` 的异常保证恢复 Job 状态、撤销栈；`dryRun` 不产生持久副作用。
2. 明确“命令执行成功”与“领域校验通过”的两级语义。Agent 默认不接受 `validate.ok:false` 的最终修改；允许 UI 草稿态，但不得越过制造导出门。
3. `cablab_batch` 增加 `atomic:true`、失败整批回滚、返回逐条结构化回执；旧非原子调用保持兼容或显式标记。
4. 宿主文件写入（`bench.rules.set`/`layout.write`/`presets.write`）不能靠 Job 快照回滚：用隔离工作树/临时文件 + 原子替换，定义路径白名单，批内失败恢复；只用 JS 命令白名单不宣称 Shell 沙箱。
5. 为异常、运行时非法状态、无权限动词、批次第 N 步失败、撤销栈一致性各写负面测试。

**DoD**：以上每种负面测试都能证明“失败前后 Job/文件哈希相同（除允许的日志）”；`npm run verify:ci` 全绿。

## A02 · 制造输出与语义回归补洞（P0）

**改动入口**：`cli.mjs` / ZIP 导出器、`generators/_lib/pins.ts`、`snapshotDiff.ts`、`scripts/diff-snapshots.mjs`、两仓制造回放。
1. 修 `file.export-cnjob --path`：真正写 ZIP（`manifest.json` + `snapshot.json`），并给出 SHA256、Schema/数量信息；若希望仅输出 JSON，另用显式 `--snapshot-json`，不得伪装为 ZIP。
2. 增 `centerline` 槽路径、孔、内外轮廓、加工面、板厚、材料等制造敏感字段的 Pins/Diff 断言；补一例“槽偏移 5 mm 但旧 Pins 认为无变化”的失败先行测试。
3. 端到端：Cab 导出 ZIP → Omni `VerifyJob` 导入、Nest/CAM/NC/Verify → Goldens；断言异常非零退出、制造错误禁止发布。
4. 修改 Golden 只能经显式审阅和 Troy 对制造语义的确认。特别复核 `cab_lab_kitchen` 近期 NC Y 坐标 ±50 mm 变化。
5. 既有 `audit.known.json` 豁免不得扩张为忽略新增安全问题。

**DoD**：真实 ZIP 可由 `PackageImporter.FromPath` 接受；`centerline` 变更确实导致 Diff/回归红灯；两仓完整回放绿；原有数据结构不破坏。

## A03 · Generator Agent 开发闭环（P1，Troy 提效主线）

**复用**：`agent/tasks/*.task.json`、`scripts/agent-run.mjs`、`bench.rules.*`、`bench.baseline/diff/pins/repin`、`fixtures/projects`。
**流程**：
1. Troy 给“变什么 / 不变什么 / 可接受的差异 / 验收样本”；Agent 生成 `task.json`，明确 `allow`、`allowedPaths`、`maxOps`、必须变化的 `mustChange` 与人审项。
2. 每次任务在独立 git worktree 捕获 Git SHA、Job/Generator baseline + Snapshot Golden；选择最接近的既有 module/preset；不得先改正确答案。
3. Agent 做最小必要修改：优先 `rules.json`/`layout.json`，必要时改 `generator.ts` 必须走单独的代码审查/自动测试权限；严禁写 `renderer/gen/*`。
4. 独立 verifier（不受 Agent 改写）运行 Pins、Snapshot Diff、`verify:full`、真实工程 cases、Omni Golden；报告板 ID、板尺寸、材料、Face、Feature、刀路影响及未通过项。
5. `bench.presets.repin` 只能在 Troy 接受具体路径后执行，且跨范围改变直接失败。
6. 输出 `report.md` + `transcript.jsonl` + 变更文件/哈希/测试证据 + `APPROVE/REJECT/REVISE` 待办；未经批准不更新 Golden/不自动合并。

**DoD**：至少 1 个 Troy 确认的非平凡变更和 1 个故意越界变更；正例能拿到完整审阅包，越界/漏检/测试红灯必然拒绝；Reject 可恢复原基线。

## A04 · OmniCam Agent Facade v1 实施（P1）

**改动入口**：`dotnet/src/CabinetNC.Application/Projects/ProjectSession.cs`、`dotnet/src/CabinetNC.FusionPackage/`、`dotnet/tools/VerifyJob/`、`dotnet/src/CabinetNC.Verify/`；参考 [Omni v2](https://github.com/yzhan722/cabinetnc-cut/blob/devops/docs/agent/INTERFACES-v2.md)。
- 先建**无 UI、只读/验证优先**的 Application Facade：`omni.import`、`omni.inspect`、`omni.validate`、`omni.run-pipeline`、`omni.verify-export`；返回统一 JSON 结果 + 确切退出码。
- 可复用现有 Domain/PackageImporter/VerifyJob，但不得将 CLI 与 `MainWindow.xaml.cs` 耦合；禁止复制第二套 Nest/CAM 算法。

**DoD**：命令行可导入当前 Cab Lab 的真实 ZIP 并输出单条 JSON 验证结果；不依赖 WPF；验证失败无 NC 发布副作用；相关 Domain/Verify/Package 测试与 Windows CI 绿。

## A05 · 跨仓自动验收 + 领域案例库（P1）

1. 将 `fixtures/projects` 从当前 1 个真实项目增加到至少 **5 个由 Troy 确认**的不同模块案例，含成功与出口受阻案例、可回放原始输入和批准的 Snapshot。
2. Cab `cnjob` 真正 ZIP 与 Omni Golden **版本钉死**，CI 的单独集成 job 拉取指定 SHA 的两个分支代码、运行固定工具链及 `VerifyJob`；不允许依赖未经记录的工作目录或旧 DLL。
3. 差异报告必须区分“有意领域规则变化”“意外回归”“只改变序列化/时间戳”；NC 对位置/深度/刀具变更仍须 Troy 决策。
4. 来源信息、变更原因及制造审核人写入 `CASE.md`；禁止无理由批量更新基线。

**DoD**：任意端故意修改制造关键字段引发红灯；CI 报告定位到 Workpiece/Feature/Sheet/NC；5 个案例可重复回放。

## 给编程 AI 的不可变执行规则

1. 先读本 PRD、对应 v1/v2 接口和源码；发现矛盾优先实码，先记录差异再改文档。**不要因 PRD 凭空实现大量已有能力**。
2. 只在指定开发分支派生 `feature/agent-*`；单任务最小 diff，**严禁强推、改 main/upstream、动用户本地 WIP**。
3. Job/Board/`cnjob 1.1` 不能随意改；若确需破坏性变更，另提交 ADR/迁移方案/兼容测试，等待人审。
4. 先复现失败并加测试，再改代码；不能通过扩大白名单、修改 Golden、忽略错误来让 CI 变绿。
5. 每个 PR 包含：修改范围、风险、验证命令/结果、Golden 差异、可回滚步骤、需要 Troy 决策的制造语义。
6. Agent 的命令白名单不是安全沙箱；有 Shell 权限时必须用隔离工作树、文件白名单/目录限制和受控凭据。
7. 单面加工 Snapshot A、不允许双面盲加工、生产 NC 安全门必须保留；不向真实 CNC 自动上传/执行。
8. 不要新建“万能 Agent 基础平台”；优先打通 **一个真实 Generator 任务**，证明可重复后扩展。

**完成标准**：A01–A05 满足各自 DoD，两个指定分支 GitHub CI 全绿；至少 1 次真实需求被 Troy 明确 ACCEPT，才可宣称本月 Agent 开发闭环完成。
